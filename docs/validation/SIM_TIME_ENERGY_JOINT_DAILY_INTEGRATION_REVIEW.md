### 4.2 五类时刻与请求策略

旧路径每小时计算一次请求，读取上一小时末 SOC，没有独立的观测/快速执行时钟。其策略是 PV 富余充电、SOC 高于 reserve 时放电，不会因低于软保电目标而主动网充（S3）。联合入口策略在低于目标且许可允许时可提出最大充电请求（S7）。这两者不是同一控制器。

**v2 建议首版只使用现有联合 `_request`，在元数据中标识 `joint_reserve_v1`；旧 Demo 仍使用原策略。**不复制策略公式、不向联合入口暴露任意 callable，也不把旧策略作为可切换的首版运行选项。

修订理由：旧 `_battery_request` 返回原始 PV−load，可能超过 3 kW；联合 `_request` 本身限制到 ±3 kW。联合执行器计算 `target_pv_cap` 时先使用 `battery_target` 估计吸收能力，实际 PCS 限幅在后续物理层。若直接注入旧策略，存在“按超过 PCS 能力的请求预留 PV 吸收量”的路径。源码反例推演：PV=5.8、load=1、SOC 未满时，旧请求为 +4.8 kW，PCS 实际最多 +3 kW；若限发目标仍按 +4.8 计算，可能留下馈网。此处是只读路径分析，**不是已运行失败用例**。直接支持旧策略需要单独审阅请求到执行目标的限幅关系，不能藏在薄适配中。本方案通过继续使用既有联合策略避免该扩展，而不是悄悄改写旧原始请求。

不同策略的请求、能量和 SOC 可以不同；比较时先列出请求差异，再解释物理与执行约束影响。固定同一请求序列的物理对照复用既有旁路方法，不把旧实际功率当新请求，也不要求两个闭环策略产生相同能量。

| 时刻 | 拟保持的合同 |
| --- | --- |
| EMS | 默认 3600 秒，24 次：0 至 82800；物理细分、观测、显示不增开决策；t=86400 只收尾 |
| 观测/执行检查 | 动态每 60 秒检查，读取 20 秒前事实，10 秒后生效；启动未成熟不能预知 t=0 事实。理想模式零延迟并允许事实事件额外检查，不等于动态模式 |
| 执行效果 | 延迟效果按既有顺序成熟；许可恢复不能复活被撤销锁存的旧正向请求，需新 EMS tick |
| 物理 | 3600/60/15 秒仅是最大步；仍在事件、效果、SOC、既有一秒离散爬坡更新处切段；不把阶梯爬坡画成已验证的连续执行器 |
| 记录/显示 | 当前 executor 的 record/display 参数不控制 EMS，现有 evidence 导出完整账本。新的图表重采样应为纯读取视图，不是第二次积分或另一运行时钟 |

### 4.3 功率、效率、拓扑与状态

- 两条路径均为单 AC 母线：**电池正为充电、负为放电；电网正为购电、负为售电**。`grid = load + actual_battery - delivered_PV`，不反转旧符号以迁就阶段性描述。
- 旧 Demo 默认电池 10 kWh、充放电上限均 3 kW、双向效率各 0.95、reserve 0.2、初始 SOC 0.5。联合入口当前 `battery()` 恰为同一参数，但不是从旧输入传入；适配必须显式传同一参数，不能因默认值巧合相同就称兼容。
- 新入口仅保留一份物理 SOC；EMS 只读该状态反馈。硬 SOC 下限沿用 BatteryParameters.reserve_soc，软目标为单独字段；不能把软目标当作新的物理容量下限。
- 充电：储能增量=AC 充电能量×充电效率；放电：储能减量=AC 放电能量/放电效率。signed battery energy=storage delta+conversion loss；损耗不再从 AC 母线扣第二次。
- EMS 原请求、执行约束后请求、实际电池交付必须分列。旧模型在整小时计算可行平均功率，新模型可能先按较大功率到界，再停止。即使小时末 SOC 和净电量一致，小时内功率及购售电仍可能不同。
- PV 输入在本轮视为 **AC 侧可用功率**，不是未经建模的 DC 面板功率；没有额外 PV 逆变效率模型。弃光=可用 AC 能量−实际交付，不隐含新的 DC 损耗。

依据 S2–S4、S6、S8。不增加设备、测量可信性或真实 PCS/BMS 能力。

#### 4.3.1 功率能力边界

### 4.4 能量、违规与不可满足目标

共同状态的每个物理片段直接保留可用/交付/弃光 PV、负载、电池有符号交付、储能变化、转换损耗、购电和售电。小时及日报只能聚合这些片段；电池充/放、购/售必须分别累加，不能先算小时平均再取正负。原字段 `battery_throughput_kwh` 对应绝对交付能量，不是净电量。

网充来源沿用单母线剩余量口径：充电超过实际 PV 减负载的正余量部分计为 grid-to-battery；它是仿真拓扑核算，不是真实电力来源追踪。许可为 off 的响应期间仍如实记 prohibited energy；Zero Export 为 on 时的馈网按峰值、持续时间和电量审计，模式 off 时的售电仍留在账本，但不误算为该约束违规。

必须保留既有 14 条动态 excursion 和 12 条保电软目标未达的基线记录。**12 是原 26 组场景的记录数，不是新 24 小时运行预定必须出现的数量。**新运行应报告真实缺口，不能为得到相同数量而改结果。现有联合 `passed` 只覆盖执行预算，不表示软目标达成。现有软目标 finding 是终点缺口；过程曲线可展示，但不能宣称已验收全天目标达成时限。

无限外部电网供负载是当前模型边界；无停电/孤岛供能模型，不能凭空填“未供负载=0，因此抗停电通过”。旧日报无费用字段，即使输入有 tariff，也不代表已验证经济收益；本次最小接入不新增费用算法。

#### 4.5.1 字段字典与核算合同

以下 `dt_h=(end_s−start_s)/3600`，每个实际片段恰好计一次；能量源是唯一 ledger，不是图表采样、EMS 请求或墙钟。累计列是片段能量前缀和，不能再次积分。

| 字段/输出 | 单位和符号 | 来源与累计/展示方法 |
| --- | --- | --- |
| `start_s/end_s`、UTC 起止 | s；相对起点；UTC 带偏移文本 | 实际 ledger 端点；不以记录频率生成物理时长 |
| `original_request_kw` | kW；+充电/−放电 | EMSDecision/ledger，保持到下一 EMS；只展示，不计物理能量 |
| `constrained_request_kw` | kW；+充电/−放电 | 执行约束后 ledger；不当作已交付 |
| `actual_battery_kw` / `battery_kwh` | kW/kWh；+充/−放 | 物理结果；有符号 AC 能量为 actual×dt_h |
| `charge_kwh/discharge_kwh`（新汇总列） | kWh，均非负 | 分别对 `max(actual,0)×dt_h`、`max(−actual,0)×dt_h` 求和；throughput=两者之和，不是净值 |
| `soc_before/soc_after/final_soc` | 0–1 的容量比例；图可显示 % | 物理状态，不求和；明确小时末 SOC 与小时起点 timestamp 的区别 |
| `grid_kw` | kW；+购/−售 | `load+actual_battery−delivered_PV`，允许负值；不得夹零 |
| `import_kwh/export_kwh` | kWh，均非负 | 分别 `max(grid,0)×dt_h` 和 `max(−grid,0)×dt_h`；小时/日分别求和，不净额抵消 |
| `available_pv_kw/kwh` | kW/kWh，非负 | caller AC 可用事实及其片段积分；不拿 cap 代替可用量 |
| `delivered_pv_kw/kwh` | kW/kWh，非负 | 执行器实际 AC 输出及其积分；不是请求 cap |
| `curtailed_pv_kw/kwh` | kW/kWh，非负（数值容差内） | 可用−交付；小时/日求和；非零不得伪装为转换损耗 |
| `load_kw/load_kwh` | kW/kWh，非负 | 不可改写的输入负载及其积分 |
| `storage_delta_kwh` | kWh，充正放负 | `10×(soc_after−soc_before)`；累计等于起终储能变化 |
| `conversion_loss_kwh` | kWh，非负（容差内） | `battery_kwh−storage_delta_kwh`；不再从 AC grid 扣除；没有另建 PV 侧损耗 |
| `grid_to_battery_kwh` | kWh，非负 | `max(0,actual_battery−max(delivered_PV−load,0))×dt_h`，单 AC 母线核算，不是设备溯源测量 |
| `prohibited_grid_charge_kwh` | kWh，非负 | 源许可 off 时累计上述网充，包含响应期；不能按延迟的 effective permission 洗掉违规 |
| Zero Export excursion | peak kW、duration s、energy kWh | 源 Zero Export on 且实际 grid<0 的事实；与全部售电分列，保留事件时刻/观测/效果/是否截断 |
| 网充 excursion | peak kW、duration s、energy kWh | 源许可 off 的实际电池网充；普通购电供负载不算；按唯一物理行计量 |
| `reserve_target_soc`、`reserve_gap_soc`（新视图） | 0–1 比例 | caller 目标与 `max(target−SOC,0)`；目标是软目标，不改硬 SOC 界 |
| `reserve_gap_kwh`（终态及视图） | kWh 储能缺口，非负 | `10×reserve_gap_soc`，不是达到目标所需的 AC 购电量；不能把每行缺口求和当耗能；终态沿用现有 finding |
| 状态/原因 | 枚举/文本 | `completed` 仅说明运行完成；执行验收、软目标未达、未收束/未覆盖分别列示，不合并成误导性总 PASS |

恒等式分别检查：`PV_available=PV_delivered+PV_curtailed`；`load+battery−PV_delivered=import−export`；`battery=storage_delta+loss`。小时平均功率为对应片段功率×交集时长之和/3600，不用于恢复购售电；曲线包含全部事件转折，规则采样只增加视图点，不抹去峰值。

### 4.6 异常、重放、恢复与回退

当前执行器每次调用从初始状态重新计算，没有持久队列、暂停恢复、重复调用去重或断点续算 API。固定输入、策略和配置可从 t=0 确定性重放；重新调用后再追加旧累计数会重复计算，不能称为安全恢复。

输入失败应在运行前拒绝；运行或输出异常终止并记录失败，不能自动切回旧引擎继续本次 SOC。完成标志仅在全部输出成功后生成；新的 failed manifest 是拟增加的输出封装，不是当前能力。日末未到期效果或未闭合 excursion 必须留痕，不补上虚构停止时刻。

代码恢复包可恢复源码和重跑，不能恢复中途 PV cap、观测/执行队列、锁存状态。旧入口回退只能另开目录从完整初始输入重跑，不混合两套账本。

### 6.2 从源码参数推导响应与能量

读取依据：S8 的 `CurtailmentSettings`、`_checks`、`_move_cap` 及主循环；S9 的 `_excursions`。原参数是检查周期 60 s、观测事实年龄 20 s、效果延迟 10 s、PV cap/output 每秒最多变动 1 kW。没有另一个经过验证的设备采样率、通讯时延或 PCS 爬坡指标。

对于整数秒事件 e，第一次能看见它的检查是 `c=60×ceil((e+20)/60)`，许可效果为 `a=c+10`。故 `a−e < 20+60+10=90 s`（保守使用不严格的 90 s 上界）。例如 e=4000 时 c=4020、a=4030，许可门响应 30 s；e=40 时 c=60、a=70，30 s；e=41 时 c=120、a=130，89 s。启动单列：首次检查 60、采样 40、效果 70；不是一律用 70 s 代替任意事件上界。

**两个逐秒环节的区别：**从效果时刻 a 起，cap 首次改变在 a+1；cap 从 0 到 6 最多 6 步。actual output 的上升定时器在首次出现余量时再等待一秒，因此从 0 升到 6（或本输入的 5.8）最迟 a+7，而不是 a+6。两环节流水推进，不是简单串加 6+6。降 cap 时 actual output 随较低 cap 下降，没有同样的额外上升等待。这里的 7 s 针对固定目标、固定可用 PV、无中途反转的源码路径；不是对任意切换序列的形式化证明。
