# Grid-charge permission revocation interlock — pre-run acceptance contract

Baseline: local commit `43a7932c7a3d30329bdbbd2d6ab2b205104a1345`, clean `baseline/sim-time-energy` worktree. This is a separate simulation-only acceptance entry. It does not modify `DailySimulationRunner`, the frozen `time_energy` physics, PV curtailment, EMS strategy, device adapter, hardware, or any protocol.

## Three layers and time contract

1. **EMS** reads current SOC and external facts only at scheduled control instants `0, 3600` simulated seconds. It uses the existing simple imbalance/reserve request rule and holds its requested kW until the next tick. A permission event is not an extra EMS decision.
2. **Execution interlock** samples permission and PV/load facts only on its own fixed check clock (`0, 60, 120, ...` seconds by default). A check at `t` sees the right-continuous facts from `max(0, t-observation_delay_seconds)`; the result becomes effective at `t+execution_delay_seconds`. The default **simulation hypotheses** are check period `60 s`, observation delay `20 s`, execution delay `10 s`; all three are explicit caller parameters, not PCS/BMS performance claims. No event-driven check is implemented. A physical input event can split a slice, but it never silently advances the execution clock.
3. **Physics** receives the execution-constrained battery request in explicit contiguous `PowerInterval`s and computes delivered power, SOC and import/export via the unchanged `simulate_time_energy`. Intervals split at external facts, EMS ticks, execution checks, execution-effect instants and SOC boundaries. Record/display cadence cannot trigger either decision layer.

At one timestamp, the deterministic order is: new external facts become current; already-scheduled execution effects mature; a scheduled EMS tick may produce a **fresh** request; scheduled execution sampling uses the stated delayed facts; then physics integrates the following half-open interval. With zero execution delay a sample maturing on the check timestamp is applied before that timestamp's EMS tick. Repeated identical revoke facts do not create a new permission transition or reset an energy accumulator.

Sign convention remains battery `+charge/-discharge`, grid `+import/-export`, with `grid = load + delivered battery - PV`. Permission **off** prohibits grid-to-battery charge, not grid purchases for load and not PV-to-battery charge. Under the existing single AC-bus model there is no separately metered source tag. For this simulation we explicitly assume PV serves load first, then battery; the observed PV surplus is `max(PV-load,0)`. While permission is off, or while an old positive request is latched after a revoke, execution charge request is capped at the latest *effective observed* surplus. This probe requires complete deterministic PV/load facts: unavailable or untrusted source information is **outside its demonstrated input contract**, never silently converted into a claim of safe PV charging. A PV/load change after an effective off gate can make that observation stale: the physical layer uses current facts, and the resulting short-term grid-to-battery charge is recorded as a **new source-change transient**, not relabeled as permission-revoke lag or concealed. This can prove only zero **model-net grid charging after relevant facts have been observed and their effects applied**, under the declared bus allocation; it cannot prove physical electron provenance or a certified device interlock.

Revocation invalidates the current positive EMS request for automatic resumption. Restoring permission changes the gate state after the same explicit delays but does **not** replay the old high-power request; only a later scheduled, fresh EMS decision may remove its latch. This is the no-unfounded-jump rule. Discharge requests are not constrained by this charge-only interlock.

## Predeclared latency, power, and energy acceptance

- Scenario duration `[0,7200)` seconds. Battery capacity 10 kWh, charge/discharge limits 3 kW, efficiencies 0.95, hard SOC floor 0.2. Primary EMS period is 3600 s. The three physical steps are 3600/60/15 s with the **same** external facts, EMS times and execution check/effect schedule.
- Source revoke is effective at its stated external event timestamp. The first matching delayed observation cannot take effect later than `observation_delay + check_period + execution_delay = 20+60+10 = 90 s` afterward (default configuration). This is a conservative budget, not a measured device latency. For 3 kW charging, maximum prohibited grid-to-battery energy during that budget is `3 kW × 90/3600 h = 0.075 kWh` plus numerical tolerance. For `observation_delay=0`, revoke exactly on a 60 s check boundary and 10 s execution delay, the expected stop delay is exactly 10 s and the energy is `3×10/3600 = 0.008333333333 kWh`.
- Once the effective off transition **and the latest PV/load observation effect** have both matured, in a stable no-PV or insufficient-PV interval prohibited grid-to-battery power and energy must be zero within `1e-10 kW` and `8e-11 kWh` respectively. If PV surplus is lost while the gate is already off, the separate source-change response uses the same predeclared `90 s` upper latency and `3×90/3600 = 0.075 kWh` conservative energy bound; it is never claimed to be instantaneous. The old scenario's 1.5 kWh prohibition breach is retained as **pre-interlock failure evidence**, not rewritten as a PASS.
- Power balance tolerance `1e-10 kW`; event-time comparison `1e-9 s`; SOC and cross-step SOC `1e-9`; energy conservation and cross-step totals `4e-11 kWh × simulated hours` (2 h = `8e-11 kWh`). Per-slice energy checks use the same rate with a one-second floor. Each physical result must remain within SOC `[0.2,1]` and ±3 kW battery limits.
- Record/display frequency changes alone must not change EMS decisions, executor checks/transitions, interval requests, SOC or energy. Physical step changes must stay within the above tolerances. A different EMS or execution check period is **not** an integration-equivalence assertion.
